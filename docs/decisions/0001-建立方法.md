# 0001 建立 workflow 的方法

- 日期：2026-10-17
- 狀態：已採用

## 背景

這個 repo 要建立個人 workflow 的 skill-set。在實際寫 skill 之前，需要先定好方法，並決定使用者在什麼時候介入。

## 選項

1. 直接挑一套既有的 skill set 修改。
2. 先從既有的 skill set 抽出「面向」，由使用者對每個面向表態，再據此設計 skill。

## 決定

採用選項 2，分成六個階段（見 `docs/method.md`）。使用者在每個階段都有固定的介入方式：決定、確認、核准、提供素材。

## 原因

- 每套 skill set 背後都有一組設計立場，例如 Matt Pocock 是「使用者當技術主管」，pstack 是「agent 依原則自主判斷」。直接挑一套，等於接受它全部的立場。
- 把面向拆開來決定，可以混合不同來源的做法，也讓每個選擇都有理由可查。
- 面向分成通用與領域兩類，之後延伸到其他領域時可以重複使用。
